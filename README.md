# MyCloud Learn Lab — 나만의 AWS 디지털 트윈

AWS 콘솔에서 클릭하며 VPC를 만들고, EC2를 시작하고, S3에 파일을 올리고,
RDS를 생성하는 그 "흐름"을 그대로 연습할 수 있는 나만의 미니 콘솔입니다.
**Docker도 필요 없고, AWS 계정도 필요 없어요.** `node` 하나만 있으면 됩니다.

> 이건 실제 aws.amazon.com이 아니라, 그 화면 구성과 클릭 흐름을 본떠 만든
> 개인 연습용 웹앱이에요. 실제 리소스가 클라우드에 생기지는 않지만, 화면
> 구조·용어·순서는 최대한 진짜와 비슷하게 맞췄습니다. 수업 때 배운
> **EC2 / VPC / Storage 워크숍 가이드**의 개념들을 반영해서, 기본 개념뿐
> 아니라 실습에서 다뤘던 세부 설정까지 콘솔 위에서 눌러볼 수 있게
> 확장했습니다.

## 실행 방법

```bash
git clone https://github.com/develop-jw/mycloud-learn-lab.git
cd mycloud-learn-lab
npm install
npm start
```

브라우저에서 `http://localhost:4000` 접속하면 끝입니다.

## 화면 구성 (MyCloud Learn Lab)

학습 플랫폼 형태의 서비스 디자인이에요. 로고·아이콘은 모두 직접 그린
오리지널이고, AWS 로고나 공식 아키텍처 아이콘은 쓰지 않았습니다.

| 영역 | 설명 |
|---|---|
| **상단 헤더** | 로고, 리소스 검색(이름·ID·종류), "리소스 만들기" 빠른 생성 메뉴 |
| **내비게이션 바** | 홈 · VPC · EC2 · S3 · RDS · 실습 가이드, 리전/사용자 표시 |
| **좌측 메뉴** | 실제 AWS 콘솔처럼 **들어간 서비스의 하위 메뉴만** 보여줘요 (예: VPC → 서브넷/라우팅 테이블/보안 그룹…). 아래쪽에 실습 진행률이 붙어 있어요. 홈과 실습 가이드는 넓게 쓰도록 좌측 메뉴가 없습니다. |
| **대시보드** | 히어로 + 실시간 아키텍처 다이어그램, 나의 실습 여정(7단계), 지금 배울 개념, 서비스 바로가기, 환경 상태 점검, 최근 활동 |
| **실습 가이드** | 3-Tier 웹 서비스 구성 7단계. 리소스를 실제로 만들면 자동으로 완료 처리돼요. |
| **모바일** | 폭이 좁아지면 좌측 메뉴는 가로 스크롤 탭으로, 대시보드는 한 줄 배치로 바뀌어요. |

### 실시간 아키텍처 다이어그램

`인터넷 → 인터넷 게이트웨이 → VPC → 가용 영역 → 퍼블릭/프라이빗 서브넷 → 인스턴스`
순서로 그려지고, VPC 안의 RDS는 "데이터 계층", VPC 밖의 S3는 "리전 서비스"
영역에 따로 표시돼요. 인스턴스/DB가 생성·시작 중이면 점이 깜빡이고,
상태가 바뀔 때까지 대시보드가 2초마다 자동으로 갱신됩니다.

### 환경 상태 점검

실제 AWS의 Trusted Advisor 느낌으로 가볍게 점검해요: 보안 그룹 없는 인스턴스,
SSH(22)가 0.0.0.0/0에 열린 보안 그룹, 퍼블릭으로 열린 버킷/DB,
연결 없이 남은 EBS 볼륨(비용), 분리된 인터넷 게이트웨이.

> 글꼴은 Pretendard(CDN)를 불러오고, 인터넷이 안 되면 시스템 글꼴로 대체돼요.

## 무엇을 연습할 수 있나요

| 메뉴 | 실제 AWS 콘솔과 비교 |
|---|---|
| **VPC → 내 VPC** | "VPC 생성" → CIDR 블록 입력. VPC를 만들면 실제처럼 **메인 라우팅 테이블이 자동으로 같이 생성**됩니다. |
| **VPC → 서브넷** | 서브넷을 만들면 자동으로 해당 VPC의 메인 라우팅 테이블에 연결돼요. 어떤 라우팅 테이블에 연결되어 있고 그 테이블에 인터넷 게이트웨이 라우트(`0.0.0.0/0 → igw-...`)가 있는지에 따라 **퍼블릭/프라이빗이 실시간으로 계산**됩니다 — 실제 AWS와 똑같은 방식이에요. |
| **VPC → 라우팅 테이블** | 라우팅 테이블을 새로 만들고, 라우트(대상 CIDR + 타깃)를 추가/삭제하고, 서브넷을 연결/재연결할 수 있어요. 메인 테이블은 삭제할 수 없고, 서브넷이 연결된 테이블도 삭제가 막혀요 (`DependencyViolation`). |
| **VPC → 보안 그룹** | 인바운드 규칙 추가/**개별 삭제**. 보안 그룹은 **스테이트풀**이라 인바운드만 허용하면 응답 트래픽은 자동으로 통과한다는 설명이 화면에 있어요. |
| **VPC → 네트워크 ACL** | 서브넷 단위 방화벽. 인바운드/아웃바운드 각각 규칙 번호·프로토콜·포트·CIDR·허용/거부를 설정할 수 있고, 보안 그룹과 달리 **스테이트리스**(거부 규칙도 명시적으로 필요)라는 차이를 화면에서 바로 확인할 수 있어요. |
| **VPC → 인터넷 게이트웨이** | 생성(분리 상태) → VPC에 연결 → 라우팅 테이블에 `0.0.0.0/0` 라우트 추가까지, 실제 "퍼블릭 서브넷 만들기" 4단계를 그대로 밟아볼 수 있어요. VPC당 1개만 연결 가능하다는 제약도 있습니다. |
| **EC2 → 인스턴스 시작** | 이름 → AMI 카드 선택 → **인스턴스 패밀리 탭**(범용/컴퓨팅 최적화/메모리 최적화/스토리지 최적화/가속 컴퓨팅)별 인스턴스 유형 카드(vCPU/메모리/프리 티어 표시) → 키 페어 → VPC/서브넷/보안 그룹 → **루트 볼륨 크기·유형** → **구매 옵션**(온디맨드/스팟) → **IMDSv2 필수화** 체크박스 → **사용자 데이터(User Data)** 부트스트랩 스크립트까지, 실제 콘솔의 고급 설정 흐름을 그대로 반영했어요. 시작하면 실제처럼 **대기 중(pending) → 실행 중(running)** 순서로 상태가 바뀌고 퍼블릭 IP와 **루트 EBS 볼륨이 자동 생성**됩니다. |
| **EC2 → 볼륨(EBS)** | 볼륨 생성(크기/유형/가용 영역) → 인스턴스에 연결(**같은 AZ가 아니면 연결 거부**) → 분리(루트 볼륨은 분리 불가) → 스냅샷 생성 → 삭제(사용 중이면 거부). 인스턴스를 종료하면 루트 볼륨은 같이 삭제되고, 추가로 붙인 볼륨은 분리만 됩니다. |
| **S3** | 버킷 만들기(이름 규칙, **버전 관리**, **퍼블릭 액세스 차단** 옵션 포함) → 버킷 열어서 파일 업로드 시 **스토리지 클래스**(Standard/Intelligent-Tiering/Standard-IA/Glacier/Deep Archive) 선택. **이 부분은 진짜로 동작해요** — 업로드한 파일이 실제 디스크에 저장되고, 퍼블릭 액세스 차단이 켜져 있으면 실제 S3처럼 직접 URL 접근이 **403 AccessDenied**로 막힙니다. |
| **RDS** | "데이터베이스 생성" → 엔진(PostgreSQL/MySQL) 선택 → 인스턴스 클래스/사용자명/비밀번호 → VPC 연결 → 생성. **생성 중(creating) → 사용 가능(available)**로 바뀌면서 실제와 비슷한 형태의 엔드포인트 주소가 발급됩니다. |

추천하는 연습 순서: **VPC 생성 → 서브넷 생성(퍼블릭/프라이빗) → 인터넷 게이트웨이 생성·연결 → 라우팅 테이블에 IGW 라우트 추가 → 보안 그룹/네트워크 ACL 설정 → 그 위에서 EC2 인스턴스 시작 → S3 버킷 만들어서 이미지 업로드 → RDS 생성.**
이 순서 자체가 실제 AWS에서 3-tier 웹 서비스를 올릴 때의 일반적인 흐름입니다.

## 재미있게 봐두면 좋은 디테일

- **의존관계 보호**: 서브넷/인스턴스가 남아있는 VPC, 서브넷이 연결된 라우팅 테이블/네트워크 ACL, 연결된 인터넷 게이트웨이, 객체가 남은 S3 버킷, 사용 중인 EBS 볼륨은 삭제가 안 돼요 (`DependencyViolation` 에러). 실제 AWS도 똑같이 동작합니다.
- **퍼블릭/프라이빗 서브넷 판정**: 하드코딩이 아니라 "이 서브넷이 연결된 라우팅 테이블에 IGW로 가는 라우트가 있는가"를 매번 계산합니다. 같은 서브넷도 라우팅 테이블을 바꾸면 퍼블릭 ↔ 프라이빗이 실시간으로 바뀌어요.
- **같은 AZ 제약**: EBS 볼륨은 인스턴스와 같은 가용 영역(AZ)에 있어야만 연결할 수 있어요.
- **버킷 이름 검증**: 대문자를 쓰거나 너무 짧으면 실제 S3처럼 거절당해요.
- **비밀번호 비노출**: RDS 마스터 비밀번호는 생성 후 목록 조회 API에서 절대 다시 내려주지 않습니다 (실제 AWS도 마스터 비번은 재조회가 안 돼요).

## 이번에 의도적으로 빼놓은 것

수업 자료 중 **Kubernetes/EKS(쿠버네티스) 관련 내용은 이번 버전에는 넣지 않았습니다.**
`kubectl`/YAML 기반의 작업 방식은 "콘솔 클릭 흐름"이라는 이 프로젝트의 컨셉과
결이 달라서, EC2/VPC/S3(+RDS) 쪽 디테일을 더 깊게 파는 쪽을 선택했어요. 나중에 필요하면 별도 메뉴로
분리해서 추가할 수 있는 구조입니다.

## 구조

```
mycloud-learn-lab/
├── server.js          ← Express 앱 진입점 (S3 퍼블릭 액세스 차단 처리 포함)
├── lib/
│   ├── store.js       ← data/db.json 읽고 쓰는 아주 단순한 저장소
│   └── ids.js         ← "vpc-xxxx" 같은 AWS 스타일 ID 생성기
├── routes/
│   ├── vpc.js          ← VPC / 서브넷 / 라우팅 테이블 / 보안 그룹 / 네트워크 ACL / 인터넷 게이트웨이 API
│   ├── ec2.js          ← EC2 인스턴스 + EBS 볼륨 API (상태 자동 전환 포함)
│   ├── s3.js            ← S3 버킷/객체 API (실제 파일 저장, 스토리지 클래스/버전 관리/액세스 차단)
│   └── rds.js          ← RDS 인스턴스 API
├── data/db.json       ← 만든 리소스가 저장되는 곳 (첫 실행 때 자동 생성, Git 제외)
├── uploads/           ← S3에 올린 실제 파일 (Git 제외)
└── public/
    ├── index.html      ← 헤더 / 내비게이션 / 좌측 메뉴 / 푸터 뼈대
    ├── style.css       ← 디자인 토큰(색상·여백) + 대시보드·다이어그램·반응형 스타일
    └── app.js          ← 라우터, 대시보드(여정·점검·활동), 다이어그램, 가이드, 검색, 각 서비스 화면
```

`public/app.js` 하나에 화면 로직이 다 모여있어요. 어떤 화면이든 흐름은 같습니다:
**"목록 불러오기(GET) → 화면에 그리기 → 버튼 클릭 시 API 호출(POST/DELETE) → 다시 목록 불러오기"**.
이 패턴에 익숙해지면 실제 프론트엔드에서 API 연동하는 감도 같이 잡혀요.

## 한계 (정직하게 밝혀둘게요)

- 리소스는 `data/db.json` 파일 하나에 저장돼요. 여러 명이 동시에 쓰면 꼬일 수 있는 아주 단순한 구조라, **혼자 연습하는 용도로만** 만들었습니다.
- EC2/VPC/RDS는 화면과 상태 흐름을 흉내 낸 것이라 실제로 서버나 DB가 뜨는 건 아니에요. S3만 진짜 파일 저장이 동작합니다.
- Kubernetes/EKS, IAM(사용자/권한), CloudWatch 등은 이번 버전에는 없어요. 필요하면 이어서 확장할 수 있는 구조로 짜뒀습니다 (`routes/` 에 파일 하나 추가하는 식).
